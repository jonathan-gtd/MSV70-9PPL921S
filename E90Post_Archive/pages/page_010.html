Still Learning
After years of casual research and reading, this thread gave me the last bit of confidence I needed to swap my 2007 Z4 3.0 I single stage manifold for a 3 stage manifold. While this was a big personality change for the car and I'm now I am looking at the DME tune and I think this is the right place to ask a few simple questions. Hopefully my questions are valid for this thread and do not offend anyone.

1. It's seems to be common knowledge that the DME checks the software against a value (powerclass) in Eprom and issues a fault if the software/data does not match. This prevents people from flashing the hi output files into the lower powerclass cars. Does anyone know if this is strictly an anti tuning measure or do some sections of code refer to required specific instructions/data in another module such as the auto transmission? I've heard of a limited few successes with the powerclass setting on new or modified DMEs and no one has mentioned if the hi output file caused an issue with the auto transmission programs.

2. If I wanted to flash the higher powerclass file into my DME I would need to fix the powerclass setting within the Eprom or "fix" the bytes that the DME program checks. I'm not interested in trying to crack the DME program but I started looking into the files and have learned like many of you that the MVS 70 variants use the same program file (OPA) with different data files (ODA) so I started looking at the different data versions available for each variant. It's amazing how similar they are. While I am a complete novice at this, it seems like all of the maps, curves and constants are store in the same location. This got me comparing the 3.0 I against the 3.0 SI data files and found that only a few thousand bytes are different. Fewer between the 2.5 I and 2.5 SI. If you assume the "Secret Key" is in the same place you can use the delta between the versions to filter the possibilities even further.

If I knew the "key" was a full byte rather than a bit, I could use a few more comparisons like the equal bytes between the 3.0 SI (US) vs. 3.0 SI (EU) to narrow the list even further. I guess no one on this forum knows this answer?

I guess my next step would be to attain some type of definition file for the MSV 70 and start checking the specific values against known maps or curves.

3. Assuming I am able to dissect and rebuild a new file for my MSV70, would it be possible to simply rebuild an ODA file correct the checksums with Revtor's software and flash with WINFKP? NCS for Dummy's seems to correct the ODA file checksum on each line and the total at the end of the file. I've read that some data files are digitally signed but I can't find any signature on the MSV70 files.

If that's not an option, what is the best low cost tool for flashing this ECU, Galletto II? I'm only interested to tinker on my own car, nothing professional. I have a full time job.

Thanks in advance.

The checksums that NCS Dummy refers to are not the same as the checksums in the DME file. they are the checksums at the ends of each line of an 0DA/0PA file (intel hex format). so you would have to convert the files from Intel hex to regular binary first, make your changes, correct the DME checksum, convert it back to an 0DA file, and then use NCS Dummy to correct the checksums in the Intel hex format. then yes, you could flash it using WinKFP.

the DME checksum is a CRC32. it's pretty simple to do but you need to know what range to apply the checksum to, I haven't figured that out yet (my BDM tool corrects them for me anyway).

I think Galletto can do it but I've been talking to a guy in Germany and he's having lots of problems with his. There has to be an alternative to $300 flash cables, really all you need is a $25 D-CAN cable and software. something like BMWflash for E90s...

you can't flash a 330i tune to a 325i because WinKFP checks the part numbers and knows you don't have a 330i. It has nothing to do really with the tune physically working or not.

however, if you had a full dump of a 330i, you could copy your VIN/relevant information and flash that file over and it would work with no problems. except you probably don't want a 330i tune without the 3-stage manifold. you can copy sections out of the 330i tune that make sense though (vanos/valvetronic). Most of the tunes are actually identical.

the best way to do that would be to update to the newest software version in WinKFP (currently 049PP0L921S I believe). download a full dump of that, and copy the parameter section over from a 330i file with the same version (from 0x40000 to 0x7FFFF). Then flash it. You wouldn't even have to correct checksums as there are separate checksums for the parameter and program space, as long as you don't change any tune data.

IMO, using WinKFP to do custom flashes is a waste of time. It's way too complicated for what we need it to do. All we need is a generic way to flash over OBD. It's probably feasible to do basically the same thing as above however, you would leave the part # in the header at the top of the parameter space the same as a 325i, but the actual parameter space would be copied over from a 330i. I'm pretty sure the part # header isn't covered by the checksum. WinKFP would then flash it because the part #s would match.
